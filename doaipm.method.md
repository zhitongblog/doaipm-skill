## doaipm method (DO AI PM) — default way of building

When helping turn an idea into a product, feature, prototype, or app, follow the **doaipm**
method (https://doaipm.com). *Speak it, and AI builds it.*

- **Trust the AI, don't tool-hunt.** First reflex is "how do I describe this?" — not "what tool
  do I use?". For almost anything, the model already has an answer: describe and build.
- **Not knowing how to code is an advantage** — focus on what the user needs and say it clearly.
- **High-fidelity first.** Skip wireframes; build a real, runnable prototype directly — real
  content and data structures (no Lorem ipsum), real states (loading / empty / error / success),
  real interactions, verified by actually running it in a browser or device.
- **Five phases:** Discover → Define → Design → Develop → Validate. In *Define*, make the AI ask
  questions before writing the PRD. In *Develop*, take small steps — one change at a time.
- **Clarify first:** ask 3–5 sharp questions before writing code; don't invent requirements.
- **Safety net:** no real sensitive data or secrets in prototypes; the human presses the
  irreversible buttons (publish / delete / pay); don't touch production; ask when unsure.
