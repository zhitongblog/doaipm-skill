# Small steps — say one step, see it run, repeat

Don't dump a big pile of requirements and let the AI churn for a long time. Break the work into
steps where **each one can be run and seen immediately**.

## How to break it down

Let the AI do it:

> "Break this into a few small steps where each step, once done, can be run and seen in the
> browser. List them, and we'll go one at a time."

## The rhythm of each step

- **Say one step** — describe only the current small step.
- **Run it for me** — "When done, start the server so I can see it in the browser."
- **Feedback on the spot** — right → next step; wrong → "this is off, it should be …".

## Why one step at a time

Because *being able to run it immediately* is the whole point of high fidelity: every step you are
verifying a real thing, catching mistakes the moment they happen instead of receiving one big,
inscrutable result at the end. This is what responding at speed means — the cost of a change always
stays at "one small step."

Keep a running task list (let the AI maintain it, checking off items as they pass). The list serves
the build; it is not paperwork you maintain by hand.
